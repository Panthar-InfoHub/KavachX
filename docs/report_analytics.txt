1. FULL CODEBASE ANALYSIS
================================================================================

1.1 Frontend Framework & Core Architecture
- Framework: Next.js 16.2.6 (App Router architecture)
- Core Libraries: React 19.2.4, TypeScript 5.x
- Styling Engine: Tailwind CSS v4 with custom brand typography (Syne, Plus Jakarta Sans, Inter)
- Rendering Model: Static Site Generation (SSG) and Server Components by default, paired with interactive Client Components ("use client").
- Root Entry Point: app/layout.tsx is the global shell wrapping every page with fonts, SEO schemas, toast providers, and all third-party analytics scripts.

1.2 Analytics-Related Files Map
1. Analytics Dispatch Hub:
   - lib/analytics.ts: Centralized singleton module containing type definitions (AnalyticsEvent), helper methods (trackEvent, trackMetaPageView, trackMetaEvent), and fail-safe dispatch logic for GA4, Meta Pixel, and Microsoft Clarity.
2. Analytics Ingestion Components:
   - <GoogleAnalytics />: Injected in app/layout.tsx (line 128) from @next/third-parties/google.
   - <ClarityAnalytics />: Implemented in components/clarity-analytics.tsx, rendered in app/layout.tsx (line 126).
   - <MetaPixel /> & <MetaPixelTracker />: Implemented in components/meta-pixel.tsx, rendered in app/layout.tsx (line 127).
3. Event-Triggering UI Components:
   - components/cta.tsx: Contact form lead submission (generate_lead, form_error) and social links (social_link_click).
   - components/navbar.tsx: Desktop and mobile header CTAs (cta_click).
   - components/kairos-page-client.tsx: Partner and pre-order CTAs (cta_click).
   - components/vendor-page-client.tsx: Partner onboarding CTAs (cta_click) and accordion toggles (faq_toggle).
   - components/suraksha-hero-button.tsx & components/cta-steps.tsx: Google Play download intent (app_download_intent).
   - components/suraksha-kavach-section.tsx & components/kairos-section.tsx: Homepage showcase CTAs (cta_click).
   - components/faq.tsx: Homepage accordion toggles (faq_toggle).
   - components/blog/blog-card.tsx & components/blog/featured-blog-card.tsx: Blog publication card clicks (select_content).
   - components/footer.tsx: Global footer social media links (social_link_click).

1.3 Environment Variables
- NEXT_PUBLIC_GA_MEASUREMENT_ID: Google Analytics 4 Measurement ID (Configured: G-NM0FYHXDER in .env.local).
- NEXT_PUBLIC_CLARITY_PROJECT_ID: Microsoft Clarity Project ID (Configured: ydfm0q7tlk in .env.local).
- NEXT_PUBLIC_META_PIXEL_ID: Meta (Facebook) Pixel ID (Configured: 1686673549111473 in .env.local).

1.4 API Routes & Server Actions
- Server-side Analytics Ingestion: NONE. There are no custom API routes forwarding events to GA4 Measurement Protocol, Meta Conversions API (CAPI), or Clarity server endpoints. All tracking calls are initiated strictly in the client browser.
- Lead Ingestion: Handled via Next.js Server Action lib/mail.action.ts (sendMsgAction). Form state and analytics dispatch occur inside client component components/cta.tsx upon receiving { success: true }.

1.5 Authentication & CMS Administration
- Admin authentication is located at /admin/login using Better Auth (signIn.email in lib/auth-client.ts).
- The admin panel at /admin/* is strictly an internal dashboard for managing blog posts.
- Intentionally Excluded: Internal admin sign-ins, blog creations, edits, and deletions do NOT call trackEvent(), ensuring employee workflows never pollute marketing metrics. No public-facing user signup/login flow exists.

This automatically injects the Google Tag script (https://www.googletagmanager.com/gtag/js?id=${gaId}) with strategy="afterInteractive", ensuring tag evaluation never blocks the browser's First Contentful Paint (FCP) or Largest Contentful Paint (LCP).

- Configured in .env.local as G-NM0FYHXDER.

2.3 Page-View Tracking
- Initial Page Load: Automatically logged by gtag('config', gaMeasurementId) initialized by @next/third-parties/google.
- Client-Side SPA Navigation: Handled automatically by GA4 Enhanced Measurement ("Page changes based on browser history events", monitoring HTML5 history.pushState and popstate).
- Manual vs. Automatic: FULLY AUTOMATIC. The codebase intentionally contains no manual gtag('event', 'page_view') dispatches. This prevents duplicate page-view inflations on Next.js route changes.

    import { useEffect } from "react";

    let isInitialized = false;

    export function ClarityAnalytics() {
      useEffect(() => {
        const projectId = process.env.NEXT_PUBLIC_CLARITY_PROJECT_ID?.trim();

          Clarity.init(projectId);

4. META (FACEBOOK) PIXEL REPORT
================================================================================

4.1 Initialization Mechanism
- Source Location: components/meta-pixel.tsx
- Mounted In: app/layout.tsx (line 127)
- Script Injection Strategy:
  - Injected via Next.js <Script id="meta-pixel" strategy="afterInteractive"> loading https://connect.facebook.net/en_US/fbevents.js.
  - Executes fbq('init', '${pixelId}').
  - Critical Design Choice: fbq('track', 'PageView') is OMITTED from the inline script tag. Instead, all PageView dispatches are delegated to the <MetaPixelTracker /> component to avoid duplicate page views on initial load.
  - Includes a <noscript> image fallback:
    <noscript><img height="1" width="1" style="display:none" src="https://www.facebook.com/tr?id=${pixelId}&ev=PageView&noscript=1" alt="" /></noscript>

4.2 Pixel ID Configuration
- Sourced from process.env.NEXT_PUBLIC_META_PIXEL_ID?.trim().
- Configured in .env.local as 1686673549111473.

4.3 PageView Tracking Architecture
- Implementation: The client component <MetaPixelTracker /> resides inside a <Suspense> boundary in components/meta-pixel.tsx:
    function MetaPixelTracker() {
      const pathname = usePathname();
      const searchParams = useSearchParams();
      const lastTrackedUrl = useRef<string | null>(null);

      useEffect(() => {
        const queryString = searchParams?.toString();
        const currentUrl = queryString ? `${pathname}?${queryString}` : pathname;
        if (lastTrackedUrl.current === currentUrl) return;
        lastTrackedUrl.current = currentUrl;
        trackMetaPageView();
      }, [pathname, searchParams]);

      return null;
    }
- Initial Load vs. Client Route Changes:
  - On mount, lastTrackedUrl.current is null, sets currentUrl, and calls trackMetaPageView().
  - On subsequent SPA route transitions, useEffect detects URL change, updates ref, and calls trackMetaPageView().
  - Deduplication: React 19 Strict Mode re-mounts do not duplicate PageView because lastTrackedUrl.current === currentUrl evaluates to true.

================================================================================

| Dimension                 | Google Analytics 4 (GA4)                       | Microsoft Clarity                          | Meta Pixel                                   |
|---------------------------|------------------------------------------------|--------------------------------------------|----------------------------------------------|

| Audience Retargeting      | Google Ads Audience Builder                    | No                                         | Meta Custom Audiences & Lookalike Audiences  |
| Execution Point           | Client-side (@next/third-parties/google)       | Client-side (@microsoft/clarity NPM)       | Client-side (next/script inline injector)    |
